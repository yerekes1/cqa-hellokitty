# CQA: оценка качества диалогов

Прототип команды **HelloKitty** для хакатона Freedom Broker CQA. Система оценивает работу оператора по настраиваемому чек-листу на русском, казахском и английском, показывает реплики-доказательства, принимает апелляции и пересчитывает итог.

## Запуск

Нужен Python 3.12.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
```

Заполните в `.env`:

- `GEMINI_API_KEY`: бесплатный ключ с https://aistudio.google.com/apikey
- `ORGANIZER_API_URL`: адрес кнопки GET из гайда организаторов, без параметра `group_id`
- `TEAM_NAME`: название команды

Запустите интерфейс и откройте http://127.0.0.1:8000:

```powershell
.venv\Scripts\python app.py
```

На экране «Оценка набора» введите `group_id` (например, `DEV`), нажмите «Загрузить», затем «Оценить весь набор».

## Оценка из командной строки

Сохраните ответ API организаторов в файл, затем:

```powershell
curl.exe "<адрес API>&group_id=DEV" -o data/dev.json
.venv\Scripts\python grader.py --input data/dev.json --out results/dev/results.json
.venv\Scripts\python check_results.py results/dev/results.json data/dev.json
```

Если прогон прервался, `--resume` оценит только недостающее, а `--only ID1,ID2` повторит выбранные диалоги.

Контрольный набор обрабатывается одной командой: получение данных, оценка, повтор неудачных, проверка формата и отправка в Git.

```powershell
.venv\Scripts\python prod.py --group <group_id> --push
```

## Как это работает

```
API организаторов -> сервер -> транскрипт как есть, нумерация с 1
                                     |
            блок фактов (код) + чек-лист с подсказками из настроек
                                     |
                       один вызов модели, JSON по схеме
                                     |
        проверка (код): значения, шкалы, N/A, номера реплик, сверка с фактами
                                     |
                итог и флаг (только код) -> SQLite, results.json, интерфейс
```

- **Новые диалоги читает модель.** Готовых ответов нет. У каждой оценки сохраняются модель, версия чек-листа, хэш промпта, токены и сырой ответ; журнал открывается в карточке диалога.
- **Итог и флаг считает код** (`cqa_score.py`), поэтому ошибки в сумме исключены. При N/A вес перераспределяется, грубая ошибка отмечается отдельно и итог не обнуляет.
- **Чек-лист меняется без правки кода.** Промпт и схема ответа собираются из настроек, подсказки хранятся внутри критерия и уходят вместе с ним.
- **Код не меняет ответы модели.** Если ответ спорит с фактами, модель получает один повторный запрос, а расхождение попадает в очередь «Проверить человеку».

## Модели и стоимость

Значения задаются в `.env`. Фактически использованная модель указывается в поле `model` файлов `results/*/results.json`.

| Назначение | Модель | Стоимость |
|---|---|---|
| Чаты, DEV и интерфейс | `gemini-3.5-flash-lite`, бесплатный тариф Gemini API | $0 |
| Чаты, контрольный набор | `gemini-3-flash-preview`, резерв `gemini-3.5-flash-lite` | $0 |
| Звонки | локальная модель через Ollama, настройка `VOICE_MODEL` | $0 |

Звонки содержат реальные данные, поэтому в бесплатный облачный тариф они не отправляются.

## Структура

| Файл | Назначение |
|---|---|
| `checklist.default.json` | Начальный чек-лист: 8 критериев, веса, шкалы, правила N/A |
| `grader.py` | Сборка промпта, вызов модели, проверка ответа, выгрузка результатов |
| `llm.py` | Вызов Gemini и Ollama |
| `scene_facts.py` | Факты о диалоге: первая реплика оператора, удержание, конец разговора |
| `cqa_score.py` | Итог, секции и флаг |
| `check_results.py` | Проверка `results.json` по формату организаторов |
| `app.py`, `web/` | Сервер и интерфейс на HTML, CSS и JavaScript без сборки |
| `results/` | Результаты по наборам DEV и контрольному |

Интерфейс работает через REST, адрес сервера задан одной настройкой в `web/app.js`, сборка не нужна. Это упрощает перенос в HTML-компонент Dynamics 365.
